# Arabic and English

Arabic is the default language at `/`, right to left. English mirrors it under `/en`. Every
page carries its language in its address. There is no stored preference to fall back on, and
the language switch is a link to the same page in the other language.

## One rule for addresses, on both sides

The default language's pages have no prefix. Every other language's pages sit under
`/<code>`. The rule is written once on each side, and the two mirror each other:

| | Frontend (`src/config/site.ts`) | Server (`ozone/www/frontend.py`) |
| --- | --- | --- |
| Languages | `SUPPORTED_LOCALES` in `src/types/index.ts`; the first is the default | `SUPPORTED_LOCALES` in `ozone/locales.py` |
| A page in a language | `localePath("/", "en")` → `/en` | `localized_path("/", "en")` → `/en` |
| The base address of a path | `basePath("/en/x")` → `/x` | `resolve_page("/en/x")` → `(page, "en", "/x")` |

Helpers are named by role (`basePath`), not by language. blinktech, where English is the
default, has the same rule with the languages swapped.

## Messages

`src/i18n/locales/{ar,en}/` hold the messages, one file per area: `common.ts` (brand, nav,
language, theme, footer) and `hero.ts`. Each language's `index.ts` combines them.

- **Arabic is the source of truth.** `MessageSchema` is `typeof ar`, and the locales test
  checks that `en` has exactly the same keys and list lengths.
- **Lists** (the tagline's items) are arrays. Read them with `tm()` and `rt()`, as
  `BrandTagline` does.
- vue-i18n reserves `@ { } | $` in messages. Keep emails, URLs and phone numbers out of
  messages; they come from Ozone Settings (step 3).

## Shared with the server: `meta.json`

`src/i18n/locales/meta.json` is read by the SPA and by the server
(`ozone/locales.py` `shared_json()`), so the two never differ:

| Key | Holds | Read by |
| --- | --- | --- |
| `paths` | Each page's base address (`"landing": "/"`) | `config/site.ts` `pagePaths`, `frontend.py` `resolve_page` |
| `site` | The company's name in each language | `brand.name` messages, `og:site_name` |
| `ar`, `en` | Each page's title and description | `meta` messages (the tab title), the server's `<title>` and meta tags |

The server reads it once per process. After editing it, restart the web workers (a deploy
does). With `bench start`, saving any of the app's `.py` files reloads them.

## Language on screen

`router/guards.ts` calls `setLocale(to.meta.locale)` before each navigation. That sets
vue-i18n's locale and `<html lang dir>`, and re-translates the tab title. On a full page load
the server has already rendered both (`seo-head.ts`), so the first paint is in the right
direction.

## Adding a page in both languages

1. Add its base path to `meta.json` `paths`, and its title and description under `ar` and
   `en`.
2. Add `...localizedRoutes("<page>", "<Name>", () => import("@/views/<Name>View.vue"))` to
   `router/routes.ts`. That makes `<Name>` (Arabic) and `<Name>En` (English).
3. Add a `website_route_rules` entry for its Arabic path in `ozone/hooks.py`. English is
   covered by `/en/<path:app_path>`.
4. To show it in the header and footer, add `{ id, page }` to `navItems` in `config/site.ts`, and
   `nav.<id>` in both languages. The sitemap lists it on its own.
5. Run the tests: routes, locales, and `ozone.tests.test_frontend`.

`/capabilities` was added this way.
