# TypeScript Setup

The same setup as blinktech's (`apps/blinktech/docs/frontend/typescript.md`).

## Config files

| File | Covers | Notes |
| --- | --- | --- |
| `tsconfig.json` | — | Solution file that only references the two below (`vue-tsc -b`) |
| `tsconfig.app.json` | `src/**/*.ts`, `src/**/*.vue`, `components.d.ts` | Browser code, `strict`, `@/*` → `src/*` |
| `tsconfig.node.json` | `vite.config.ts`, `vitest.config.ts`, `tailwind.config.ts`, `vite-plugins/*.ts`, `types/*.d.ts` | Node-side config files |

Non-default options in `tsconfig.app.json` match frappe-ui's own: `lib: ESNext`,
`types: ["vite/client", "unplugin-icons/types/vue"]` (for `~icons/lucide/*`) and
`allowImportingTsExtensions`.

## Type declarations

| File | Declares |
| --- | --- |
| `src/env.d.ts` | `window.site_name`, `window.csrf_token`, `window.site_contact` (the server-rendered boot data) |
| `types/frappe-ui-config.d.ts` | Types for `frappe-ui/vite` and `frappe-ui/tailwind`, which ship as JS without types |
| `components.d.ts`, `auto-imports.d.ts` | Generated by frappe-ui's vite plugin. Do not edit |
| `src/types/index.ts` | Shared app types: `SUPPORTED_LOCALES`/`LocaleCode`, `PageKey`, `NavItem`, `SocialPlatform` (must match the DocType's Platform options), `SiteContact` (what `site_contact.py` returns), `ServiceId`, `IndustryId`, `EquipmentItem`, `Stat` |

## Why `yarn type-check` filters errors

frappe-ui publishes raw `.ts` and `.vue` source, so vue-tsc type-checks it along with our code
and reports strict-mode errors inside `node_modules/frappe-ui`. `scripts/type-check.mjs` runs
`vue-tsc -b`, hides the diagnostics under `node_modules/`, and fails if any of ours remain.
**Exit 0 means our code is clean.** Plain `npx vue-tsc -b` always fails; use
`yarn type-check`.

## Where it's enforced

`yarn build` and `bench build` don't run the type check, so a type error never blocks a
deploy. CI does: the `Frontend` job in `.github/workflows/ci.yml` runs `yarn type-check`,
Biome and the tests on every push and pull request.

## Conventions

- `<script setup lang="ts">` in every SFC.
- Import types with `import type` / `type` modifiers.
- Typed records over strings where TypeScript can check completeness:
  `ICONS: Record<ServiceId, Component>` fails to compile when a service has no icon.
