## Routing

`src/router/routes.ts` holds the route table and the typed `RouteMeta`. Every route sets
`meta.layout`, and `App.vue` wraps the view in that layout. Unknown paths redirect to their
language's landing page (`/x` → `/`, `/en/x` → `/en`).

Public pages come in pairs from `localizedRoutes()`: `Landing` at `/` (Arabic) and `LandingEn`
at `/en`. Each carries `meta.locale` and `meta.page` ([i18n.md](i18n.md)).

On a full page load, Frappe decides what to serve. `/` is the SPA because of
`home_page = "frontend"`, and `/en`, `/en/<path>` because of `website_route_rules` in
`ozone/hooks.py`. Any other top-level path needs its own rule, or Frappe answers with its
own 404 before the SPA loads.

## Production

1. `yarn build` (or `bench build --app ozone`, through the root `package.json`) writes the
   bundle to `ozone/public/frontend/`, then copies its `index.html` to
   `ozone/www/frontend.html`.
2. frappe-ui's `jinjaBootData` plugin adds a Jinja loop to that HTML, which sets each key of
   `context.boot` on `window`.
3. A request for `/` renders `www/frontend.html`. `www/frontend.py` `get_context()` supplies
   `boot`:
   - `csrf_token`, committed so a GET request keeps it;
   - `site_name`;
   - `site_contact`, from Ozone Settings ([server.md](server.md#boot-data)).

   `no_cache = 1` keeps the token fresh.
4. `seo-head.ts` has turned `<html>` and the `seo:start … seo:end` block into Jinja.
   `context.seo` (`seo_context()`) fills them: `lang`/`dir`, title, description, canonical,
   hreflang alternates (`ar`, `en`, `x-default` → `/`), Open Graph tags, and `noindex` for
   an address that isn't a page. Texts come from `meta.json`, through `ozone/locales.py`.

## Development

`yarn dev` serves the app on `:8080` and proxies backend requests to Frappe on `:8000`
(`frappeProxy`). The dev page has no boot data. Code that needs `window.*` values gets them
from an API instead: `useSiteContact` calls `ozone.api.site.get_site_contact`.
