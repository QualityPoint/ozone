# Architecture

## Folder layout

```
apps/ozone/
├── package.json                 # postinstall / build / dev run in frontend/, so bench build builds the SPA
├── frontend/
│   ├── index.html               # the shell; <html lang="ar" dir="rtl">
│   ├── vite.config.ts           # frappe-ui plugin: dev proxy, Jinja boot data, Lucide icons, build paths
│   ├── tailwind.config.ts       # frappe-ui preset
│   ├── vitest.config.ts         # standalone: unit tests don't need frappe-ui's dev plugins
│   ├── tsconfig{,.app,.node}.json
│   ├── biome.json
│   ├── scripts/type-check.mjs   # vue-tsc, ignoring errors inside node_modules/frappe-ui
│   ├── types/frappe-ui-config.d.ts
│   └── src/
│       ├── main.ts              # bootstrap only: router, styles, mount
│       ├── App.vue              # picks the layout from route.meta.layout
│       ├── env.d.ts             # window.site_name, window.csrf_token
│       ├── router/              # index.ts (history, scrolling), routes.ts (table, RouteMeta), __tests__/
│       ├── layouts/             # PublicLayout.vue
│       ├── views/               # LandingView.vue
│       └── assets/styles/       # main.css
├── ozone/
│   ├── hooks.py                 # home_page = "frontend"
│   ├── www/frontend.py          # get_context(): boot data
│   ├── www/frontend.html        # generated by yarn build (gitignored)
│   └── public/frontend/         # generated by yarn build (gitignored), served at /assets/ozone/frontend/
└── docs/frontend/               # these docs
```

Folders such as `components/`, `composables/`, `i18n/`, `config/` and `services/` are added as
the steps that need them land, following [conventions.md](conventions.md).

## Routing

`src/router/routes.ts` holds the route table and the typed `RouteMeta`. Every route sets
`meta.layout`, and `App.vue` wraps the view in that layout. Unknown paths redirect to `/`.

On a full page load, Frappe decides what to serve. `/` is the SPA because of
`home_page = "frontend"`. Any other top-level path needs a `website_route_rules` entry in
`ozone/hooks.py`, or Frappe answers with its own 404 before the SPA loads. `/en` gets its
rules in step 2.

## Production

1. `yarn build` (or `bench build --app ozone`, through the root `package.json`) writes the
   bundle to `ozone/public/frontend/`, then copies its `index.html` to
   `ozone/www/frontend.html`.
2. frappe-ui's `jinjaBootData` plugin adds a Jinja loop to that HTML, which sets each key of
   `context.boot` on `window`.
3. A request for `/` renders `www/frontend.html`. `www/frontend.py` `get_context()` supplies
   `boot`:
   - `csrf_token`, committed so a GET request keeps it;
   - `site_name`.

   `no_cache = 1` keeps the token fresh.

## Development

`yarn dev` serves the app on `:8080` and proxies backend requests to Frappe on `:8000`
(`frappeProxy`). The dev page has no boot data. Code that needs `window.*` values gets them
from an API instead, starting in step 3 (`useSiteContact`).
